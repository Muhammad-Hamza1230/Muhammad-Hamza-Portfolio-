QA Documentation Case Study

Login Testing

A focused manual-testing case study for authentication workflows, validation and negative scenarios.

Objective

Verify that users can log in with valid credentials and receive clear, safe feedback for invalid or incomplete inputs.

Coverage

  • Valid email + valid password
  • Wrong password / wrong email
  • Empty fields
  • Invalid email format
  • Password visibility and validation

Sample Test Case

TC-LOGIN-001: Login with valid credentials

Precondition: Registered account exists.

Steps: Open login → enter valid email → enter correct password → click Login.

Expected: User is authenticated and redirected to the correct screen.

Negative Testing & Defect Focus

Incorrect credentials should show a useful error message without exposing sensitive information or crashing the application. Empty fields should show validation messages. I also check account lockout behavior, session handling and consistent error states.
