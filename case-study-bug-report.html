Bug Report Practice

A defect-management case study focused on clear reproduction steps and useful severity/priority information.

Bug Report Format

  • Clear defect title
  • Environment / build
  • Preconditions
  • Steps to reproduce
  • Expected result
  • Actual result
  • Severity & priority
  • Evidence and notes

Example Defect

Title: Login crashes after incorrect password

Severity: High

Priority: High

Expected: Clear authentication error and user remains on login screen.

Actual: Application closes/crashes after incorrect password.

Defect Lifecycle

New → Assigned → In Progress → Fixed → Retest → Reopened if necessary → Closed. I focus on making reports reproducible so developers can diagnose and fix issues efficiently.
